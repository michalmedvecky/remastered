# Independent browser integration review

Reviewed the browser host, native build script, timer patch, probes, SDL2 input adapter, and native save path logic on 2026-11-18. This was a static review of the compiled source integration, not execution of the original DOS program. Findings below record issues as found; the root implementation can subsequently resolve them.

1. **Save mount configuration (high):** `tools/build-native.py` initially wrote `global_data_dir` / `personal_data_dir`, whereas native `File_Init` reads `datadir` / `savedir` (`src/file.c`). `/data` was also supplied at compile time, masking the former issue; personal saves would miss the `/save` IDBFS mount. During this review the generated config was updated to `datadir=/data` and `savedir=/save`; verify a real save/reload in the browser.
2. **Save import names (high):** native `GenerateSavegameFilename` uses `_save%03hu.dat`, while the initial host accepted and wrote only `SAVE###.DAT`. Such imports do not appear, and exported `_save###.dat` files cannot be reimported by that validator. Accept both filename forms and normalize to the native underscore form. Native `GetSavegameCount` stops at the first missing index; importing a high slot into an empty browser requires a contiguous-slot strategy or an explicit visible-slot mapping.
3. **Keyboard focus (medium):** installed SDL2 2.32.10 defaults `SDL_HINT_EMSCRIPTEN_KEYBOARD_ELEMENT` to window in `SDL_emscriptenevents.c`. The host has other focusable controls and modal dialogs. Without setting the hint to the canvas, typing in browser controls also feeds the original game input queue, and navigation keys may be swallowed. Use the canvas hint before `SDL_Init`, and restore canvas focus after browser dialogs close. SDL2 already registers mouse-up on document and resets keyboard state on window blur; no additional stuck-key claim is made for that path.
4. **Persistence close window (medium):** the initial host syncs every 2.5 seconds and starts an asynchronous sync on `pagehide`; page termination need not wait for IndexedDB completion. Installed Emscripten `src/lib/libidbfs.js` supports `{autoPersist:true}` on mount, persisting writes when files close and queueing another operation if writes occur during a sync. This narrows the loss window. A browser test should save, wait for a confirmed completed transaction, reload, and load the mission.
5. **Timing claims and background policy (medium):** cooperative `emscripten_sleep(4)` retains the native scheduler's callback intervals: MPU 120 Hz, game/GUI 60 Hz, and dropped missed `callonce` render callbacks. It does not establish cycle-exact DOS timing. The unchanged `Timer_GetTime` uses wall-clock `gettimeofday`; a large background interval or clock reversal produces a large unsigned delta and a potentially long `Timer_InterruptRun` catch-up loop. A monotonic `emscripten_get_now` path and an explicit background-tab policy would avoid clock-reversal stalls. Verify hide/resume behavior in the actual browser build.

The terrain fixture scope is separate: 51 complete generator cases (48 distinct mission seeds plus three diagnostic seeds), and terrain-only MAP projections from 66 scenario files. The full native loader creates objects before terrain overrides; those occupancy and ground-icon mutations are outside the isolated terrain oracle. See `coverage-summary.json` and `README.md`.
