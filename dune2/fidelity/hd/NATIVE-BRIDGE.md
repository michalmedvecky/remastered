# Native HD presentation bridge

The bridge observes the recovered native renderer. It does not mutate simulation objects, dirty flags, RNG, script state, clocks or input. The original indexed framebuffer is still produced by the native engine. Desktop builds compile the hooks to no-ops.

`tools/patch-native-hd.py` adds source-bound, idempotent hooks to `src/gui/viewport.c`, `src/gui/gui.c`, `src/gui/widget_draw.c`, `src/gfx.c`, `src/sprites.c`, `src/timer.c` and `src/video/video_sdl2.c`. Native command capture happens after original varargs, house-palette, widget-position, centering and dimension calculations, before original clipping/rasterization. The unmodified raster path still runs afterward.

## Payload

The synchronous `Module.duneHdPresent(payload)` callback receives an independent byte snapshot:

* `version:2`, `pixels:Uint8Array(64000)`, `palette:Uint8Array(768)` with native6-bit channels.
* `tiles:Uint16Array(600)`:15×10 cells, four words each: groundTileID, overlayTileID, houseID, isUnveiled. The native world rectangle is `(0,40,240,160)`; each tile is16×16 logical pixels.
* `commands`: native unit/effect draw records in painter order. A record has `id,x,y,width,height,flags,clip,remapCount,palette,remap,house,owner,layer`. Coordinates are original320×200 top-left positions before clipping; `clip` is `[x,y,width,height]`. `palette` is the effective16-entry mapping or null; `remap` is the exact256-entry destination mapping or null. Native flips remain in flags1/2. `0x100` is remap; `0x200` is blur.
* `uiCommands`: visible SCREEN0 sprite placements, tracked by exact native raster writes and real screen copies. Native geometry/flags/palette/remap are retained; `x/y` and `nativeClip` follow copies, including rolling credit digits. `clip` bounds currently surviving ink. `ink` consists of local `[x,y,paletteIndex]` triples, with `visibleInk`, `totalInk`, `serial` and `sourceSerial`. The original bounded128-entry pre-raster candidate cache remains under `uiCandidates` for diagnostics.
* `textGlyphs`: actual native font glyphs visible on SCREEN0, with byte `char`, `font` enum0=intro/1=new6p/2=new8p/3=other, native `x/y/width/height/advance`, effective `colours[16]`, local ink triples and the same visibility/serial fields. Spacing and line breaks follow the native glyph coordinates; entirely transparent spaces need no draw. No OCR or gameplay-text recomputation is used.
* `borders`: observed `GUI_Widget_DrawBorder` rectangles with native `widgetIndex,type,pressed,width,height`, copied positions and actual surviving rim ink. Interior labels do not invalidate the chrome rim. Generic `GUI_DrawBorder` calls outside this widget entry point are not asserted to be window records.
* `worldVisible`, `viewport` (packedcamera tile), `selectedUnit`, `selection:{position,width,height,state,type}`, `gameTick`, `playerHouse`, `veiledTileId`.
* `worldAvailable`, monotonically increasing `worldRevision`, `worldCommitTick`, `gameplayActive`, `viewportRendering`, `debugScenario`; `cursor:{id,x,y,hotX,hotY,visible}`, `message`, `screenOffset`, `cacheOverflow`.

The fixed C command ABI is16int32 fields plus16palette and256remap bytes (336bytes). The UI extension appends screen/window/serial (348bytes). Compile-time size checks guard both layouts. JavaScript consumers use named fields, not these private offsets. Pure blur commands (`flags & 0x200`, no0x100 remap) store three little-endian uint16 native values in unused remap bytes0..5, guarded by bytes6..7=`BL`: `blurOffset`, `blurIncrement`, `blurSeed`. HASREMAP remains false; real remap tables are untouched. These values are captured directly from `GUI_DrawSprite` locals before its raster loop. Palette conversion matching the SDL backend is `(sixBit*65)>>4`.

## Dirty-state and lifecycle behavior

Native world drawing is incremental. Commands persist per native unit/effect owner and are replaced only when the native renderer actually redraws that owner. Commands store world-pixel positions, so a camera change translates stationary cached objects without forcing a native draw. Native `Unit_Find` allocation/recount order is preserved within layers: worm, ground, explosions, aircraft. Shadow, body, turret, harvesting animation, smoke and selection-reticle order is retained within the owner.

Read-only pool and visibility checks prune removed/off-map/fogged owners when a viewport scene is committed, rather than when a later video callback happens. Sandworm trail visibility includes the two native previous positions. Reticle sprite6 is emitted only for the currently selected unit. An individual owner is bounded to16commands; overflow is counted, never written out of bounds. The UI cache is bounded to128entries, replaces matching keys and retains recent write serials. The original sprite-table lookup is enabled only after native loading finishes, and disabled before unloading.

Terrain descriptors are captured at each native tile raster decision. The complete scene (tiles, cached painter commands, camera and selection) is committed after `GUI_Widget_Viewport_Draw` completes its native SCREEN1→SCREEN0 viewport copies. Interface rebuilds that render only to SCREEN1 remain pending until their full viewport reaches SCREEN0. `Video_Tick` reads the committed scene and never samples a newer live map or prunes commands ahead of the displayed raster.

`worldVisible` requires a committed scene, game mode NORMAL, native targeting/placement/unit/structure selection state and zero display offset. It does not require an active game timer or a completed current drawing scope: native hint/options overlays can retain the already drawn HD world behind them. Mentat/intro states replace the viewport and remain outside this flag. `worldAvailable` separately reports retained-scene validity. Neither pause nor a live map mutation invalidates a committed scene.

Glyphs, UI sprites and widget-border rims have per-pixel provenance in all four native screens. Ordinary dirty writes clear overwritten ownership; actual transparent glyph/sprite writes preserve untouched ownership. Screen copies transfer provenance with the same clipping, overlap and skip-null behavior. GFX_CopyToBuffer/FromBuffer additionally preserve provenance through the native mouse and modal backups; restored backups are consumed and their metadata released. The native cursor is omitted from UI sprite records because its own cursor layer is presented last. At presentation, only provenance pixels whose native palette index still matches are emitted. A bounded4096-record generation-token table prevents recycled records from resurrecting stale labels without a full-screen rescan per refreshed digit. Reference counts recycle unreferenced records first, so untouched visible labels survive thousands of refreshed digits; capacity pressure is reported by `uiLedgerOverflow`. UI records share a painter serial; a copied block preserves original order within its copy epoch. Partial visibility is explicit in ink/clip, so callers must clip replacement artwork/text rather than redraw hidden portions.

The callback runs at the end of native `Video_Tick`, after normal SDL presentation. Indexed pixels include the same valid0..320-word offset used for the four extra credits scanlines; an unexpected larger offset reports the base framebuffer, with `worldVisible:false`. The browser must retain original SDL fallback for unsupported display states.

## Verification and limits

`python3 fidelity/hd/test-native-cache.py` compiles the actual cache under AddressSanitizer. It checks stationary persistence, camera translation, allocation/painter order, shadow-before-body, selected reticle removal, owner replacement/pruning, copied palette/remap data, owner overflow and bounded UI replacement. It also checks source-patcher idempotence and desktop syntax for four affected translation units. The complete bridge is compiled into the retained WASM build with the installed Emscripten/SDL2 headers. `fidelity/painted-polish/test-observer.py` additionally tests committed scene isolation, paused-world retention, UI copy relocation/overlap/transparency, partial overwrite, persistent visible labels through8192 transient records and reference-counted recycling under ASan, plus six desktop translation units and patch idempotence. `test-observer-abi.mjs` executes the actual EM_JS body against a synthetic heap to verify named fields, copied glyph/sprite geometry, border identity and stale-index rejection.

These checks verify presentation plumbing, not the visual quality of HD artwork or complete browser acceptance. Retained original combat, terrain, script and media tests remain separate. Legacy `uiCandidates` can still refer to temporary screens or overwritten sprites and are diagnostic only. Current provenance covers observed widget borders and font/sprite raster writes; arbitrary raw UI illustrations and non-widget chrome are not inferred as semantic UI. The native index witness protects against uninstrumented raw writes. Native fades/credits screen offsets still require their own presentation handling. No original DOS executable is run by these bridge tests.

## Additional overwrite and affordance hooks

The bridge distinguishes actual writes from broad dirty-area notifications. Opaque tile rasterization invalidates its written footprint even when a new palette index happens to equal an old menu glyph. Transparent tiles and raw line/checker/XOR writes invalidate only their written pixels. CPS loads clear previous screen ownership before decoding; palette-only remaps update native index witnesses. Nonfilled border/wired-rectangle dirty notifications are notification-only, so portrait interiors remain visible. The exact native GFX_DrawTile and GUI_DrawBorder functions are compiled into the ASan regression fixture for these cases.

Direct GUI_DrawBorder calls emit native rectangles with `fill`, `schemaIndex`, `widgetIndex:-1`, `type:-1`; direct button schema0 means pressed. The existing widget wrapper preserves its actual widgetIndex/type/pressed, suppressing nested duplicates. Border provenance owns only the exact outer pixel rim, preserving the first interior portrait row.

`Module._dune_hd_refresh()` publishes the current framebuffer, palette, committed scene and UI observations with the last actual native screen offset. It performs no native draw, dirty notification, timer advancement or gameplay mutation. The offset is retained before the callback-enabled gate so enabling painted mode while paused can request its first current frame immediately.

## Stable source text and camera margins

The complete GUI_DrawText line is now retained as `textRuns`, with literal CP437-decoded text, source bytes, full geometry/glyph advances and exact current coverage clips. `uiPixels` provides the actual native mouse-backup underlay for witnesses; native `pixels` remains untouched. Mouse backup restores preserve saved painter order. Fit complete source layouts before applying their clips; never rebuild words from surviving ink. Details, limits and regressions are in `fidelity/painted-polish/STABLE-TEXT-CAMERA.md`.

The same committed scene publishes17×12 `overscan` terrain cells and `worldEpoch`. Centre records remain the exact15×10 raster descriptors. `_dune_hd_set_view_offset(dxQ8,dyQ8,packedViewport)` adapts only viewport screen-to-world picking using the explicitly rendered native base; zero retains the original branch. F1 Help has an explicit actual-screen replacement scope, while timer-paused F2 retains the world.
