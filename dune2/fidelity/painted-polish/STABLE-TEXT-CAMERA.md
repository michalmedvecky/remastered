# Stable native text and smooth-camera observation

The reported “Build it” corruption came from rebuilding text layout from whichever glyph ink remained visible under the mouse. The observer now captures the complete literal GUI_DrawText line, actual native glyph positions/advances, font, colours and full bounds. GUI_DrawText_Monospace retains its fixed native advances. No OCR, guessed label, font fitting or extra native drawing occurs in C.

`frame.textRuns` entries expose `runId,placementId,sourceSerial,serial,text,textBytes,x,y,width,height,font,fontHeight,colours,glyphs,ink,visibleInk,totalInk,clip,clips`. `glyphs` retains every source character, including spaces and covered characters, with absolute native positions, dimensions, advance and index. The font layout uses these complete bounds; visibility never chooses a smaller layout. Multiple copied placements may share one source runId. `clips` is a union of current logical text-coverage rectangles, copied and invalidated alongside actual native writes. It clips the fixed layout after fitting, including genuine partial screen copies and erased middle sections. The coverage is a layout rectangle, not the original glyph bitmap, so it does not impose old pixel-shaped text on new fonts. A line with no current foreground provenance is omitted.

`frame.uiPixels` is an independent native indexed witness snapshot with only the current mouse rectangle restored from its actual native backup. The original `frame.pixels` remains unchanged. Cursor drawing preserves underlying UI and text provenance; mouse restore preserves the saved paint serials instead of promoting old border fragments above the rest of the label. Consequently hovering and repeated hide/show cycles keep the same source run, full geometry, placement and painter order. Other screen/buffer copies retain their genuine paint ordering. Consumers validate glyph/icon ink with `uiPixels ?? pixels` and draw the HD cursor last.

`frame.overscan` has absolute tile origin `(cameraTileX-1,cameraTileY-1)`, width17, height12 and816 uint16 words, four per cell. Its central15×10 records are copied from the committed raster descriptors. Only the54 margin cells read the map at that same viewport commit. Out-of-map cells have visibility0, and native fog/debug flags remain authoritative. Existing native unit/effect commands already include observed one-tile fringe poses; no stale or invented unit poses are added. Callback arrays and objects are independent JavaScript copies suitable for retained RAF presentation. `worldEpoch` changes when a world scene is invalidated.

`_dune_hd_set_view_offset(dxQ8,dyQ8,packedViewport)` receives displayed D minus native N in signed1/256 logical pixels, together with the exact rendered frame’s native viewport. The nonzero viewport picker uses that explicit base, even if Cfront or live g_minimapPosition advances before the next RAF. It adds the offset before mathematical floor/tile division. Valid negative local/overscan positions select their actual world tile; absolute positions outside64×64 reject before packing. Zero offset takes the literal original picker branch. Only viewport widget43 uses this adaptation: SDL coordinates, widget hit tests, edge scrolling, minimap and cursor remain physical. No simulation rule, input queue, timer or RNG changes.

F1 Help retains STRUCTURE selection while replacing the whole front screen. Its explicit presentation-replacement scope starts immediately before the actual full Mentat SCREEN1→SCREEN0 copy and ends only after the native HUD/world restoration. This makes worldVisible false while worldAvailable stays true. F2 Options merely pauses gameplay and retains worldVisible true. Timer state is deliberately not used as the scene gate.

`test-stable-text.py` compiles the actual observer helpers under ASan and executes the actual EM_JS emitter against C snapshots. It covers middle/full cursor occlusion, repeated restore order, complete literal text, coincident-index genuine erasure, full removal, two-screen partial copies, fixed-width advances, signed-Q8 floor/roundtrip/zero behavior, explicit rendered-origin races, committed overscan centre/margins/FOW and F1-versus-F2 visibility. `stable-text-results.json` records the run. The existing observer, cache, patch-idempotence, desktop syntax and native build checks remain separate. No original DOS executable is run.

The text observer is bounded to512 retained lines and128 glyphs per line, in addition to the4096 UI-record bank. These limits are presentation-cache limits rather than evidence of whole-program recovery. Generated Emscripten JS is normalized with trailing whitespace removed line by line before hashing; this removes bundled SDL glue formatting without changing JavaScript tokens.
